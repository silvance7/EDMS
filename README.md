# 元器件管理

（！！！注意轻便版exe双击运行即居于当前目录生成数据库建议新建文件夹存放exe）
自用、完全本地的电子元器件库存管理系统 —— 托盘常驻，`Ctrl + Alt + E` 唤出浮窗，
几秒钟内知道某个器件有没有、有几个、在哪个抽屉。
**完全本地运行、不需要联网、不依赖任何服务端。**

## 快速查询（日常就靠这个）

按 **`Ctrl + Alt + E`** 唤出浮窗 → 打几个字 → 看结果 → `Esc` 关掉。

| 按键 | 作用 |
|---|---|
| `Ctrl + Alt + E` | 唤出 / 收起快速查询浮窗 |
| 输入框打字 | 实时检索，多个词用空格分开（全部命中才显示） |
| `↑` `↓` | 选择结果 |
| `Enter` | 打开主窗口并定位到该器件 |
| `Ctrl + Enter` | **快速出库 1 个**（直接扣减并记流水） |
| `Esc` | 关闭浮窗 |

左键单击托盘图标 = 快速查询，双击 = 打开主窗口。

检索是**多词 AND** 的：`10k 0603` 会同时要求两个词命中，而不是把结果搅成一锅粥。
数值带 SI 前缀展开，所以打 `10k` 能搜到存着 `10000 Ω` 的电阻，打 `100n` 能找到 `100 nF` 的电容。

### 热键被占用怎么办

Windows 上 `Ctrl+Alt+字母` 这类组合很容易被别的程序抢走（输入法、显卡驱动、
截图工具都是惯犯），所以程序**不会因为热键冲突而罢工**，而是自动降级：

1. 先试 `data/settings.json` 里配置的 `hotkey`（默认 `ctrl+alt+e`，E 取 Element / 元件）
2. 失败则按内置候选链依次尝试：`ctrl+alt+e` → `ctrl+alt+q` → `ctrl+alt+d` →
   `ctrl+alt+w` → `ctrl+alt+j`（与已配置组合相同的那一档会跳过）
3. 降级成功后**托盘弹气泡提示实际生效的组合**，以及怎么把它固定下来
4. 全部被占用时停用热键并给出提示，此时仍可点击托盘图标唤起快速查询

**想固定一个组合**：改 `data/settings.json` 的 `hotkey` 字段即可。格式如
`ctrl+shift+f9`（大小写随意）：修饰键支持 `ctrl` / `alt` / `shift` / `win`，
主键支持字母、数字、`F1`-`F24`，以及 `space` / `tab` / 方向键等常见名字。

**想知道某个组合有没有被占用**，直接试注册一次最可靠 —— 失败且错误码是
`1409`（`ERROR_HOTKEY_ALREADY_REGISTERED`）就说明已被别的程序注册：

```python
import ctypes

MOD_ALT, MOD_CONTROL, MOD_NOREPEAT = 0x1, 0x2, 0x4000
user32 = ctypes.windll.user32
kernel32 = ctypes.windll.kernel32

kernel32.SetLastError(0)
ok = user32.RegisterHotKey(None, 99, MOD_CONTROL | MOD_ALT | MOD_NOREPEAT, ord("E"))
print("空闲" if ok else f"被占用，错误码 {kernel32.GetLastError()}")   # 1409 = 已被注册
if ok:
    user32.UnregisterHotKey(None, 99)   # 测完记得释放，否则等于自己把它占上了
```

## 数据模型

两级库存，这是整套设计的地基：

```
part（物料主数据）        一个"10kΩ 0603 1% 电阻"就是一个 part
  └─ stock_lot（库存批次）  同一颗器件可以在多个位置各存一批
                            每批的数量 / 单价 / 购买日期 / 生产商 / 供应商独立记录
                            总库存 = SUM(stock_lot.quantity)
```

**为什么必须拆开**：你的字段里"价格"和"购买时间"本质上是**这一次采购**的属性，不是器件的属性。
3 月买的一批 1 分钱一颗，9 月买的 1 分 2，不拆开就记不下来。
而且同一个器件常常一半散在元件盒、一半是整盘没拆——拆开才能看到完整的位置分布。

**生产商也属于批次，不属于器件。** 同一个 10kΩ 电阻，YAGEO 买的和厚声买的是
**同一条器件记录**，只是两条采购批次——换厂牌不该逼你新建一个器件。
（`part.mpn` 型号仍留在器件上，BOM 匹配要靠它拿分。）

> 老库升级：`part.manufacturer` 会被迁移到该器件名下的每一条批次上，不丢数据。
> 见 `app/storage/migrations.py` 的 v2。

其余实体：

| 表 | 作用 |
|---|---|
| `category` | 分类树，可无限层级 |
| `param_template` | **参数模板**，由分类定义，子分类自动继承。电阻才有"阻值"，电容才有"容值" |
| `part_param` | 参数取值，数值列与文本列分开存，以支持范围筛选 |
| `location` | 存放位置树，`code` 字段是贴在抽屉上的短码（如 `A1`） |
| `stock_log` | 出入库流水。既是审计轨迹，也是库存数的重建依据 |
| `v_part_overview` | 聚合视图，列表页一次查询拿到总库存 / 批次数 / 最近采购 / 均价 |

参数模板是**参数化搜索**的钥匙：搜 `阻值 10k~100k 且 封装 0603`，
而不是在描述字符串里瞎模糊匹配。

## 性能实测

不是估算，是实测数据（测试环境：Windows / Python 3.13 / PySide6 6.9.1）：

| 状态 | 常驻内存 | 说明 |
|---|---|---|
| 冷启动到托盘就绪 | **44 ms** | 含建库、迁移、注册热键 |
| 纯托盘常驻（从未显示过窗口） | **64 MB** | 你日常的状态 |
| 同上，按过第一次热键之后 | 127 MB | 首次显示窗口时 Qt 会把绘制资源一次性加载 |
| 主窗口打开 | 140 MB | |
| 数据库文件 | 124 KB | 20 个器件 / 21 个批次 |

**64 MB 这个数字是被优化出来的**，不是天然如此。最初把快速查询浮窗在启动时就构造好，
常驻内存是 118 MB——因为构造它会把一整棵 QtWidgets 控件树拉起来。
改成**按需构造**（第一次按热键时才建），直接砍掉了 54 MB。

这和主窗口的处理是同一个思路：**常驻进程里不包含任何"用户可能今天用不到"的界面对象。**
主窗口懒加载、浮窗也懒加载，代价只是第一次按热键多花二三十毫秒——完全感知不到。

## 几个刻意的设计取舍

**为什么不用 FTS5 全文索引。**
SQLite 的 `unicode61` 分词器不切分中文——"电阻"整块当一个词，搜"电"匹配不到；
`trigram` 分词器又要求查询词至少 3 个字符，中文两字词直接失效。
而本应用规模下（≤1 万条）`LIKE` 全表扫描只要 5–20ms，本来就满足 50ms 目标。
与其供一个会坏掉的全文索引，不如用一个行为可预期、零踩坑的方案。
数据量突破 5 万条再引入不迟。

**为什么"写"和"查"是两种形态。**
真实使用频率极度不对称：录入一周几次，查询一天几十次。
所以管理界面按需打开、关闭即释放，只有托盘进程常驻——
常驻内存里不含主窗口那一整棵控件树。冷启动成本只在第一次付出。

**为什么出库不指定批次时走 FIFO。**
购买日期早的先出。这是常识性默认，能减少批次堆积和过期。
库存不足会直接抛异常，**绝不把数量扣成负数**。

**为什么入库默认合并同批次。**
"器件 + 位置 + 单价 + 购买日期 + 批次号"完全相同的采购会合并。
拆快递时一口气录十种料，列表里不会堆出十条一样的记录。
任何一项不同就新建——那本来就是不同的采购批次。

**为什么 domain 层不 import Qt。**
核心逻辑可以脱离界面跑测试、写脚本批量导入。
`.workbuddy/tools/smoke_test.py` 和 `.workbuddy/tools/ui_test.py` 就是靠这条纪律才写得出来。
将来就算换掉整个界面，业务代码一行都不用动。

## 入库 / 出库

**入库不要求先在表格里选器件。** 点「入库 +」直接开面板，顶部就是搜索框：

- 搜到 → 选中它，往下填入库资料
- 搜不到 → 列表最后一行是「＋ 新建器件「关键词」」，点它**当场建**，不用跳对话框

入库资料：**数量 / 存放位置 / 单价 / 购买日期 / 生产商 / 供应商 / 备注**。
没有批次号和订单号——那两样对自用场景是纯负担。

**生产商和供应商都是「这一次采购」的属性**，记在批次上。
拆快递是连着录十几种料，所以这两个字段会**记住上次填的值**自动带出。
位置+单价+日期+生产商+供应商都完全相同的采购会自动合并成一个批次。

**出库支持一次出多个器件**，每行可以指定从哪个批次扣（默认先进先出）：

```
用途/项目  [平衡车 v1                            ]
[＋ 添加器件]  [移除选中行]
┌────────────────────┬─────────┬──────────────────┬───────────┐
│ 器件               │ 出库数量 │ 扣减批次         │ 现有库存  │
│ 10kΩ 0603 1% 电阻  │  [ 2 ]  │ 自动（先进先出）▾│  697 / 需 2│
│ 100nF 0603 电容    │  [ 6 ]  │ #3 B2 余 200    ▾│ 1200 / 需 6│
└────────────────────┴─────────┴──────────────────┴───────────┘
```

出库同样是**全有才出**：任何一行库存不足，整批取消，一颗都不扣。
用途写进出库流水，事后能查到"这批料是用在哪个板子上的"。

> 「新建器件（纯建档，库存 0）」没有放在工具条上——建器件的正路是走入库面板。
> 只有"先建档、以后再补货"这种少见情况才需要它，所以放在表格的**右键菜单**里。

## BOM 操作：比对 / 导出 / 导入

主窗口右上角点「BOM 操作」，一个对话框里三个页签：

| 页签 | 干什么 | 典型时机 |
|---|---|---|
| **比对** | 载入 KiCad BOM，对照库存逐行匹配，一键全出库 | 画完板子、备料出库 |
| **导出** | 把当前库存的全部器件导成一份 CSV 清单 | 备份、对账、批量改数据 |
| **导入** | 从清单文件批量导入器件（建档 + 按数量入库） | 新买一批料、换机器迁移 |

### 比对：BOM 对照库存

画完原理图导出 BOM（KiCad 的 `.xlsx` 或 `.csv`），进「BOM 操作 → 比对」：

1. 选文件 → 自动逐行匹配
2. 每行给一个**状态图标**，点它才展开原因（平时不占地方）
3. 你核对或改选候选 → 勾上「参与」
4. 「一键全出库」

#### 分三档，和立创 BOM 配单的规则一致

| 图标 | 含义 | 处理 |
|---|---|---|
| ✓ 绿勾 | **完全匹配** —— 封装、参数、型号、名称全对上 | 默认勾选参与出库 |
| ⚠ 琥珀三角 | 强参数对上了，但**弱参数**（型号/名称）不吻合 | 默认不勾，点图标看原因再定 |
| ✗ 红叉 | 库存里没有能对上的器件 | 判为缺料 |

**强参数（封装 / 参数）不符的，直接不进候选。** 这条照立创官方说明定的：

> 如 BOM 中指定 0805，则仅匹配封装为 0805 的，即使参数完全相同，0603 或 1206 均不列入结果

理由很实在 —— 0603 的 10uF 和 0805 的 10uF 焊不到同一个盘上，列进候选只会诱导选错。

**但自定义封装除外。** `0.96OLED_4P`、`SMD-PCB` 这种你在 KiCad 里自己画的封装，
算法认不出对应关系，硬卡会把"其实有货"错判成缺料（实测把缺料从 30 行推到 39 行）。
所以只有**两侧都是标准封装**（0603 / 0805 / LQFP-48 / SOT-23-5 …）时才做强校验，
自定义封装只标 ⚠。被强参数排除的器件也不会凭空消失——点那一行的红叉能看到
「库里有 10uF 0805 25V X5R 电容，但封装不符」。

**弱参数不吻合不该一票否决。** 各家命名本来就有差异（`10K` / `10kΩ` /
`RC0603FR-0710KL`），一律标 ⚠ 让你自己判断。库里没记数值或没填封装时，
同样不判死，只标「无法核对」提醒你去补录数据。

**匹配度分数不显示。** 分数只在内部用来排序（匹配度高的排前面）——
看到"78 分"没法拿它做决定，看到 ✓ / ⚠ 才有用。

#### 归一化是地基，不是优化项

实测一份真实的 KiCad BOM：BOM 里 26 种封装、库存库里 14 种，**精确相等的 0 种**
——`C0603` vs `0603`、`LQFP-48_L7.0-W7.0-P0.50-LS9.0-BL` vs `LQFP-48`。
数值同理：`0.1uF` ≡ `100nF`、`22UF` ≡ `22uF`、`1k` ≡ `1K`。

**出库策略：全有才出。** 任何一行库存不足，整批取消，一颗都不扣。
出半套比不出更麻烦——你会搞不清板子上到底装了什么。
校验还是**按器件汇总**的：BOM 里同一个器件出现在多行时，
单行都够、加起来不够，同样会被拦住。

整批在**一个事务**里完成，流水备注记成 `BOM文件名 #行号`，事后可追溯。

**缺料的行可以一键建档**：建成器件档案（库存 0、预警阈值 = 需求量），
并把 LCSC 编号和厂商型号写进关键词——下次匹配直接走最高分通道。
建完档它们会出现在「只看需补货」里，相当于一份采购清单。

> `bom/` 目录不会被打进 exe，只是文件对话框的默认起点。
> 上次打开过的目录会记住（`data/settings.json` 的 `bom_dir`）。

### 导出 / 导入：器件清单的闭环

**导出**（「BOM 操作 → 导出」）一键把**当前库存的全部器件**写成一份 CSV。
用 UTF-8-BOM 编码，Excel / WPS 双击直接打开、中文不乱码。
每个批次一行，列是：

```
器件名称, 型号, 封装, 分类, 关键词, 数量, 位置, 单价, 购买日期, 厂商, 供应商, 备注
```

**导入**（「BOM 操作 → 导入」）选文件（`.csv` / `.xlsx`），先给一张
「导入后会发生什么」的预览，确认后再执行：

- 库里没有的器件 → **建档**（型号 / 封装 / 关键词 / 分类都从文件里取）
- 库里已有的器件 → **不动它的档案**，只按数量入库
  （一份格式不完整的清单，不至于把好好的档案覆盖坏）
- 数量 > 0 的行 → 走入库（和手工入库共用同一套批次合并规则）
- 分类 / 位置写**完整路径**（`电阻 / 贴片电阻`），缺的自动逐级创建
- 只想建档案不想入库：把「按文件中的数量入库」的勾去掉

导入结果会给一份**逐项的反馈**：新建了几个、入了多少行多少颗、
哪几行失败了（带行号和原因），而不是一句"成功"敷衍过去。

> **防呆**：同一份文件重复导入会重复累计库存（部分失败后重跑也一样），
> 导入确认框会专门提示这一点；导入完成后界面重置已选文件，防止手一抖再导一遍。
>
> 导出与导入用的是同一套列名，所以「导出 → 在 Excel 里改 → 导回」是个完整闭环，
> 可以拿它当批量维护器件资料的通道。

## 主题（浅色 / 深色）

默认**跟随系统**。Windows 切深浅色时界面实时跟着变，不用重启。

想固定一种，改 `data/settings.json`：

```json
{ "theme": "dark" }
```

取值 `auto`（跟随系统，默认）/ `light` / `dark`。

> **踩过的坑**：第一版在 `QWidget` 上写死了深色文字，但**下拉列表、右键菜单、
> 复选框没写样式**——它们跟随系统的深色调色板，于是黑底配黑字，完全看不见。
>
> 现在的做法是**双保险**：
> 1. 用 `QPalette` 兜住所有 QSS 没覆盖到的控件（复选框、弹出窗口、文件对话框）；
> 2. **强制 Fusion 样式**——Windows 原生样式（windowsvista）不完全跟随调色板，
>    深色下复选框仍会画成系统配色；
> 3. QSS 里显式补上 `QMenu` / `QComboBox QAbstractItemView` / `QListView`
>    这几类**弹出式顶层窗口**的样式。
>
> 改配色后必须**两套主题都实跑核对**（分别截图对比），别只看一种。

## 打包成 exe（双击就能用）

```bash
# 图标就是 ico/EDMS.ico（静态文件，仓库里有一份）。换图标 = 覆盖它再重打。
# ⚠️ 换过图标 / 改过 spec 后，先把 build/_work 目录删掉再打包 —— PyInstaller 会
#    复用上一次的 EXE 构建缓存，不清缓存的话新图标根本不会进包（实测踩过）。
# （.workbuddy/tools/make_icon.py 是备手：用代码画一个图标出来，平时用不到）

# 打包
.venv/Scripts/python.exe -m PyInstaller build/build_portable.spec --noconfirm `
    --workpath build/_work --distpath dist
```

产出一个绿色便携文件夹 `dist/EDMS/`，双击里面的 `EDMS.exe` 即可运行：

```
dist/EDMS/
├─ EDMS.exe        1.8 MB   双击启动
├─ _internal/            59 MB    Qt + Python 运行时，别动它
└─ data/                          第一次运行自动生成
   ├─ inventory.db               ← 你的全部数据就在这个文件里
   └─ settings.json              ← 热键等设置
```

整个文件夹 **61 MB**，拷到 U 盘、拷到别的 Windows 电脑上都能直接跑，数据跟着走。

**重置为空库**：删掉 `data/inventory.db`，下次启动会自动重建（默认分类和存放位置会自动灌回来）。

**⚠️ 重新打包前先备份 `data/`**：PyInstaller 的 `--noconfirm` 会先删掉整个
`dist/EDMS/`，里面的 `data/` 会跟着一起没。
更稳妥的做法是把 `dist/EDMS/` **拷一份到正式位置**（比如 `D:\Apps\EDMS\`）再运行，
以后重建只动 `dist/`，永远不碰在用的那份数据。

**数据放在哪**：固定是 exe 旁边的 `data/`，由 `app/paths.py` 决定。
绝不能放进 `_internal/` —— 那里是打包资源目录，重新打包时会被覆盖。

**几个刻意的取舍**：

| 选择 | 原因 |
|---|---|
| `onedir` 而不是 `onefile` | onefile 每次启动都要把自己解压到临时目录，冷启动 3–5 秒；onedir 直接跑，0.3 秒 |
| **不用 UPX 压缩** | UPX 压缩过的 exe 被杀软误报的概率很高，自用工具不值当冒这个风险 |
| 剔掉 16 个用不到的二进制 | 软件 OpenGL 回退（19.7 MB）、OpenSSL（7.6 MB）、QtNetwork、图片解码插件等。剔之前 93 MB，剔之后 60 MB |
| 数据不随程序走 | 便携版是独立部署，跟开发目录的 `data/` 互不影响 |

> 想要正规安装包（开始菜单项 + 卸载程序）的话，装一下 Inno Setup（`winget install JRSoftware.InnoSetup`），
> 把 `dist/EDMS/` 整个作为 `[Files]` 段打进去即可 —— 项目暂时没有现成的打包脚本。

## 日常维护

**备份**：复制 `data/inventory.db` 就是完整备份（建议连同 `-wal` 文件一起，或先退出程序再复制）。
程序内也有在线热备份能力（`Database.backup_to()`），生成的快照不会拿到写了一半的数据。

**库表结构改了**：往 `app/storage/migrations.py` 的 `MIGRATIONS` 追加 `(版本号, SQL)`，
**不要改动历史条目**。启动时会自动迁移到最新版本。

**检索结果不对**：参数模板改动后检索列需要重建，在分类树的右键菜单里加参数时会自动重建。
手工触发：

```python
from app.domain import Services
svc = Services.bootstrap()
print(svc.parts.rebuild_all_search_text())
```
